# `asana` connector

Asana as a connector: tasks, projects, sections, comments (stories), tags,
users, workspaces, search, typeahead and webhook management as verbs over the
Asana REST API (`https://app.asana.com/api/1.0`), plus a raw `api` escape
hatch — and **source events** derived from Asana webhook deliveries (task,
story, project, and a catch-all). Built on the standard library's `net/http`
and the public SDK only.

- **Kind:** connector (verbs **and** source)
- **Source:** [`connectors/asana/main.go`](../../connectors/asana/main.go)
- **Provides:** `asana`
- **Capabilities:** egress to `app.asana.com:443` only
- **Auth:** a personal access token (`token`), or conductor's managed OAuth2
  (`auth:` block + `conductor connector auth asana`)

```yaml
connectors:
  asana:
    use: asana
    token: ${ASANA_TOKEN}
    webhook:
      listen: ":9110"
      secret: ${ASANA_HOOK_SECRET}     # pinned after the first handshake — see Setup
    network: ["app.asana.com:443"]
triggers:
  - on: asana.task
    filter: { actions: [changed], fields: [completed], completed: true, projects: [Roadmap] }
    steps:
      - uses: asana.add_comment
        options: { task: "{{.gid}}", text: "🎉 {{.name}} shipped — nice work {{.assignee}}!" }
  - on: asana.story
    filter: { subtypes: [comment_added] }
    steps:
      - uses: tg.send_message
        options: { chat_id: "${TEAM_CHAT}", text: "{{.author}} on {{.task}}: {{.text}}" }
```

## Setup

### Personal access token (simplest)

You'll end up with a PAT conductor sends as `Authorization: Bearer` on every
call. It acts as *you*: it sees what you see and writes as you.

1. Sign in to Asana and open the developer console:
   [app.asana.com/0/my-apps](https://app.asana.com/0/my-apps) (or **My
   settings → Apps → Manage developer apps**).
2. Under **Personal access tokens**, click **Create new token**, name it
   (e.g. `conductor`), and click **Create token**.
3. Copy the token — Asana shows it only once.

```yaml
connectors:
  asana:
    use: asana
    token: ${ASANA_TOKEN}
```

Find your workspace gid with `uses: asana.me` (the `workspaces` list on the
result) or `uses: asana.workspaces`; resolve project/user/tag names to gids
with `uses: asana.typeahead`.

### Managed OAuth2 (optional)

`asana` also declares Asana's OAuth2 endpoints in `Describe().Auth`, so
conductor can run the authorization-code flow against
`app.asana.com/-/oauth_authorize` / `-/oauth_token`, store the refresh token,
and inject a fresh bearer token into every call. The plugin never sees the
client secret and never calls the token endpoint itself; when a managed token
is present it takes precedence over `token`.

1. In the developer console, **Create new app**, name it, and accept the
   terms.
2. **OAuth → Redirect URLs:** add conductor's callback. Asana requires
   `https` redirect URLs for web apps, so put the daemon behind TLS (or a
   tunnel) and register that URL; set it as `redirect_uri` in the `auth:`
   block. If your console accepts `http://localhost:8400/callback`, that
   works too.
3. **OAuth → Permission scopes:** grant at least the scopes this connector
   requests by default — `tasks:read`, `tasks:write`, `tasks:delete`,
   `projects:read`, `stories:read`, `stories:write`, `tags:read`,
   `users:read`, `workspaces:read`, `workspaces.typeahead:read`,
   `webhooks:read`, `webhooks:write`, `webhooks:delete` — or override them
   with the `auth:` block's `scopes`.
4. Copy the **Client ID** and **Client secret**.

```yaml
connectors:
  asana:
    use: asana
    auth:
      grant: authorization_code
      client_id: ${ASANA_CLIENT_ID}
      client_secret: ${ASANA_CLIENT_SECRET}
      redirect_uri: https://conductor.example.com/callback
      token_vault: asana
```

Then run the one-time login: `conductor connector auth asana`.

### Webhook source

Asana webhooks are registered through the API, not a settings page, and the
signing secret is **generated by Asana** during a handshake — you cannot pick
it. The flow:

1. Start conductor with the source configured but **no** `webhook.secret`
   (bootstrap mode). The listener must be reachable from Asana over public
   `https` — put it behind your reverse proxy / tunnel.
2. Register the webhook with the connector itself (or `curl`):

   ```yaml
   - uses: asana.create_webhook
     options:
       resource: "1200000000000001"          # project (or task/portfolio/team/workspace) gid
       target: https://hooks.example.com/asana
       filters:
         - { resource_type: task, action: changed, fields: [completed, assignee, due_on] }
         - { resource_type: task, action: added }
         - { resource_type: story, resource_subtype: comment_added, action: added }
   ```

   During this call Asana POSTs a handshake to `target` carrying
   `X-Hook-Secret`; the source echoes it, installs the secret, **closes the
   handshake window** (bootstrap accepts exactly one), and logs the secret
   once to stderr:

   ```
   asana[asana]: webhook handshake accepted. Pin this secret as webhook.secret so deliveries verify after a restart: 4f3c…
   ```

3. **Pin it:** put that value in `webhook.secret` and restart. From now on
   the source verifies every delivery from the moment it starts.

Without pinning, a restart loses the in-memory secret: deliveries are then
rejected (401), Asana retries with backoff, and after 24 hours of failures it
deletes the webhook. To register **additional** webhooks against the same
listener, set `webhook.handshake: true` while you create them, then add each
new secret to `webhook.secret` (it accepts a list) and unset `handshake`.

## Connection

| key | type | purpose |
|-----|------|---------|
| `token` | string | Asana personal access token, sent as `Authorization: Bearer <token>`. The fallback credential when no managed `auth:` token is present. |
| `api_base` | string | override `https://app.asana.com/api/1.0` (tests, or a proxy) |
| `webhook` | map | source transport — see below |

`webhook` keys:

| key | default | purpose |
|-----|---------|---------|
| `listen` | — | HTTP listener address, e.g. `":9110"`. **Required** for the source. |
| `path` | `/asana` | request path |
| `secret` | — | pinned handshake secret(s) — a string or a list. Deliveries signed under any of them verify. |
| `handshake` | unset | accept Asana's `X-Hook-Secret` handshake and trust the secret it installs. Unset: exactly **one**, and only while no secret is pinned (bootstrap). `true`: always. `false`: never. |
| `allow_unsigned` | `false` | accept deliveries with no / an invalid signature (explicit opt-in; logged loudly) |
| `enrich` | `true` when a credential is available | GET the task / story / project each event names, so the event carries names, assignee, projects, completion state … |
| `opt_fields` | see below | override the `opt_fields` projection used to enrich task events |

There is no `smee` relay option: Asana's handshake needs a synchronous
`X-Hook-Secret` echo in the response, which a relay cannot provide.

## Source events

Trigger with `on: <name>.<event>`. One Asana delivery carries a **batch** of
compact events; each becomes one conductor event. Deliveries are verified
against `X-Hook-Signature` (hex HMAC-SHA256 of the body under the handshake
secret, constant-time compare via `sourcekit.VerifyHMAC`) and deduplicated on
`gid + action + field + created_at + parent`. Heartbeats (`{"events": []}`,
every 8 hours) are acknowledged and emit nothing. The listener answers 200
**before** enriching, so a large batch never times Asana out.

| event | fires when |
|-------|-----------|
| `task` | a task was `added`, `changed`, `removed` (from its parent project), `deleted`, or `undeleted` |
| `story` | a story (comment or system activity) was added to / changed on / removed from a task |
| `project` | a project was added, changed, removed, or deleted |
| `event` | catch-all: anything else the webhook's filters let through (section, tag, attachment, workspace …) |

**Context** (all events): `gid`, `action`, `resource_type`, `subtype`
(`resource_subtype`), `parent_gid`, `parent_type`, `field` (`change.field`
on `changed`), `change_action`, `new_value` (when Asana includes it), `user`
(acting user's gid), `created_at`.

Enriched additions (when `enrich` is on and the GET succeeds — otherwise the
compact event streams as-is):

- `task`: `name`, `completed`, `assignee`, `assignee_gid`, `due_on`,
  `due_at`, `project` (primary/first project name), `project_gid`,
  `project_names`, `project_gids`, `section` (in the primary project),
  `sections`, `tags`, `workspace`, `url`. A `deleted` task is never fetched.
- `story`: `text`, `type` (`comment` / `system`), `author`, `task_gid`,
  `task` (the parent task's name).
- `project`: `name`, `url`, `archived`, `owner`, `team`, `workspace`.

**Filters** (evaluated by the daemon's generic list-contains evaluator —
a list matches if the context value is one of its entries, case-insensitive):
`actions`, `fields`, `subtypes`, `resource_types`, `projects`, `assignees`,
`users` (list forms); `action`, `field`, `subtype`, `resource_type`,
`project`, `assignee`, `user`, `completed` (scalar forms). `projects` /
`project` match the task's **primary (first) project** name; a task in
several projects matches only on the first. `assignees`, `projects` and
`completed` need enrichment — on a compact event those keys are absent and
the filter fails closed.

Default task enrichment projection (`webhook.opt_fields` overrides it):
`name,completed,assignee.name,assignee.gid,due_on,due_at,projects.name,memberships.project.name,memberships.section.name,permalink_url,resource_subtype,workspace.name,parent.gid,tags.name`.

> **Fail closed, by construction.** With no secret known yet, every delivery
> is rejected. Once one is known — pinned, or installed by the single
> bootstrap handshake — a handshake from anyone who can reach the port is
> **refused** (unless `webhook.handshake: true`), because otherwise an
> intruder could install their own signing key. `webhook.allow_unsigned:
> true` is the explicit, greppable way to turn verification off.

## Verbs

Selected by `uses: <name>.<verb>`. Conventions shared across verbs:

- Every request carries `Authorization: Bearer <token>` and
  `Accept: application/json`; writes are wrapped in Asana's `{"data": …}`
  envelope for you and responses are unwrapped from it.
- Every verb's outputs include `status_code`. Single-resource verbs return
  `result` (the unwrapped record); task verbs additionally hoist `gid`,
  `name` and `url` (`permalink_url`). Action verbs (add/remove/move/delete)
  return `ok: true` plus `result`.
- **Collection verbs** (`workspaces`, `users`, `projects`, `sections`,
  `tasks`, `stories`, `subtasks`, `tags`, `webhooks`) return `items` and
  `next_offset`, and share four options: `limit` (1–100), `offset` (from a
  previous `next_offset`), `all` (follow `next_page` until exhausted,
  bounded to 100 pages) and `opt_fields`.
- `opt_fields` (a list, or a comma-joined string) asks Asana to include
  fields beyond the compact `gid`/`name`/`resource_type` record, e.g.
  `[name, completed, assignee.name, due_on, permalink_url]`.
- A non-2xx response is returned as an internal error carrying the status
  and Asana's `{"errors":[…]}` body — nothing is swallowed.

Required options are marked `*`. Ids are Asana **gids** (strings).

### Identity & workspace

| verb | request | notes |
|------|---------|-------|
| `me` | `GET /users/me` | → `result` (includes `workspaces`). |
| `workspaces` | `GET /workspaces` | collection. |
| `users` | `GET /users` | `workspace`, `team`. collection. |
| `typeahead` | `GET /workspaces/{workspace}/typeahead` | `workspace` *, `resource_type` * (`task`, `user`, `project`, `portfolio`, `tag`, `team`, `custom_field`, `project_template`), `query`, `count`, `opt_fields`. → `items`. The way to turn a name into a gid. |
| `tags` | `GET /tags` | `workspace` *. collection. |

### Projects & sections

| verb | request | notes |
|------|---------|-------|
| `projects` | `GET /projects` | `workspace`, `team`, `archived` (bool). collection. |
| `get_project` | `GET /projects/{project}` | `project` *, `opt_fields`. → `result`. |
| `sections` | `GET /projects/{project}/sections` | `project` *. collection. |

### Tasks

| verb | request | notes |
|------|---------|-------|
| `tasks` | `GET /tasks` · `GET /tags/{tag}/tasks` · `GET /user_task_lists/{list}/tasks` | one selector required: `project`, `section`, `tag`, `user_task_list`, or `assignee` **+** `workspace`; plus `completed_since` (RFC3339, or `now` for open tasks only), `modified_since`. collection. |
| `get_task` | `GET /tasks/{task}` | `task` *, `opt_fields`. → `gid`, `name`, `url`, `result`. |
| `create_task` | `POST /tasks` | `name` *; one of `workspace`, `projects` (list), or `parent` (→ subtask) *. Optional `section` (gid in the **first** project — sent as a membership), `notes`, `html_notes`, `assignee` (gid, email, or `me`), `due_on` / `due_at`, `start_on`, `completed`, `tags`, `followers`, `custom_fields` (`{gid: value}`), `fields` (raw task fields, merged last). → `gid`, `name`, `url`, `result`. |
| `update_task` | `PUT /tasks/{task}` | `task` *; any of `name`, `notes`, `html_notes`, `assignee`, `due_on`, `due_at`, `start_on`, `completed`, `custom_fields`, `fields`. To clear a field use `fields: { assignee: null }`. |
| `complete_task` | `PUT /tasks/{task}` | `task` *, `completed` (default `true`; `false` reopens). |
| `delete_task` | `DELETE /tasks/{task}` | `task` *. Recoverable from Asana's trash for 30 days. → `ok`. |
| `subtasks` | `GET /tasks/{task}/subtasks` | `task` *. collection. |
| `search_tasks` | `GET /workspaces/{workspace}/tasks/search` | `workspace` *, `text`, `completed`, `assignee` / `projects` / `sections` / `tags` (lists → `*.any`), `sort_by` (`due_date`, `created_at`, `completed_at`, `likes`, `modified_at`), `sort_ascending`, `limit`, `opt_fields`, `query` (any other search parameter, e.g. `{"due_on.before": "2026-10-01"}`). → `items`. **Premium workspaces only**; no cursor pagination (Asana caps at 100). |

### Comments & membership

| verb | request | notes |
|------|---------|-------|
| `add_comment` | `POST /tasks/{task}/stories` | `task` *, `text` (or `html_text`) *, `is_pinned`. → `gid`, `result`. |
| `stories` | `GET /tasks/{task}/stories` | `task` *. collection — comments and system activity. |
| `add_to_project` | `POST /tasks/{task}/addProject` | `task` *, `project` *, `section`, `insert_before` / `insert_after`. → `ok`. |
| `remove_from_project` | `POST /tasks/{task}/removeProject` | `task` *, `project` *. |
| `move_to_section` | `POST /sections/{section}/addTask` | `section` *, `task` *, `insert_before` / `insert_after`. The task must already be in the section's project. |
| `add_tag` / `remove_tag` | `POST /tasks/{task}/addTag` · `removeTag` | `task` *, `tag` *. |

### Webhooks

| verb | request | notes |
|------|---------|-------|
| `webhooks` | `GET /webhooks` | `workspace` *, `resource`. collection — only webhooks created by this token. |
| `create_webhook` | `POST /webhooks` | `resource` * (project/task/portfolio/team/workspace gid), `target` * (public `https` URL of this connector's listener), `filters` (`[{resource_type, resource_subtype, action, fields}]`; required for workspace/team/portfolio resources). Asana handshakes `target` **during** this call — the source must already be listening. → `gid`, `result`. |
| `delete_webhook` | `DELETE /webhooks/{webhook}` | `webhook` *. → `ok`. |

### Escape hatch

| verb | request | notes |
|------|---------|-------|
| `api` | any | `method` * (`GET`/`POST`/`PUT`/`DELETE`), `path` * (relative to `/api/1.0`, e.g. `tasks/123/attachments`), `query` (map; lists comma-joined), `body` (wrapped in `{"data": …}` unless it already has a top-level `data`). → `result`, `items` (when `data` is a list), `next_offset`, `status_code`. |

```yaml
# Open a release follow-up task in the Roadmap project's "Inbox" column
# whenever GitHub publishes a release.
triggers:
  - on: gh.release
    filter: { prerelease: false }
    steps:
      - uses: asana.create_task
        options:
          name: "Post-release checks for {{.repo}} {{.tag_name}}"
          projects: ["${ROADMAP_PROJECT}"]
          section: "${INBOX_SECTION}"
          notes: "Verify the {{.tag_name}} rollout, then close this task."
          assignee: me
```

## Capabilities & security

Declares egress to `app.asana.com:443` only; the managed-OAuth2 token exchange
is conductor's, not the plugin's. Narrow per instance with `network:`; it can
never be widened past the declaration.

A personal access token carries the full permissions of the user who created
it — prefer a dedicated bot user for automation, and use the managed OAuth2
path with granular scopes when you need least privilege. Never set
`webhook.allow_unsigned` on a listener reachable from the internet; pin
`webhook.secret` as soon as the handshake has printed it.
